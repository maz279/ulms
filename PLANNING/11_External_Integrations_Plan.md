# 11 — External Integrations Plan

**Doc:** PLAN-011 · v1.0 · 2026-09-27 · Owner: Lead Developer
**Pattern for all:** hexagonal port in `mod-integration` + adapter; mock in DEV
(WireMock/containers); live sandbox in UAT; production creds only in bank
secret store; every call logged to `integration_log` (no PII payloads).

---

## 1. Bangladesh Bank CIB (Credit Information Bureau)

| Aspect | Design |
|---|---|
| Channels | (a) Monthly fixed-width Subject & Contract files via bank SFTP; (b) real-time inquiry API (where bank is enrolled) |
| Adapter | `CibPort`: `pullReport(cif)` → status; `parseFile(path)`; internal event `CibReportReceived` either way |
| Parsing | Pure parser, golden fixtures (valid/malformed/multi-subject); facility rows → `cib_facility`; raw encrypted object retained per retention policy |
| Idempotency | Dedupe by (cif, report_period, file_id); re-requests surface "already have newer" guard |
| Failure modes | SFTP unreachable → retry exp backoff ×5 then ops alert (RB-05); malformed row → quarantine record + continue; partial file never silently drops subjects |
| Reporting back | `mod-compliance` generates CIB return files from Fineract data — same fixed-width spec, sign-off chain, scheduled upload with reconciliation count vs GL |
| Testing | WireMock + fixture files in CI; UAT against bank test SFTP |

## 2. NIDW / NID e-KYC

- `NidPort.verify(nid, nameEn, nameBn, dob)` → verify result + matched fields +
reference id; async (status machine in mod-customer, officer fallback path).
- Rate limits + SLA per NIDW contract; circuit breaker; queue during outages
(offline manual verification workflow exists in prototype A2 screens).
- No full NID stored in ULMS (06 §5) — reference + masked only.
- Mock returns canned VERIFIED/REJECTED/ERROR triad; UAT against NIDW sandbox
  with bank credentials; **feature-flagged** per environment.

## 3. Payment Rails — bKash / Nagad / Rocket / BEFTN / Card

- `PaymentRailPort`: `initiate(paymentIntent) → railUrl/ref`,
  `verify(ref)`, callbacks `POST /hooks/payments/{rail}` (HMAC signed,
  timestamp ±5min, idempotent by UTR per 05 §7).
- **Portal/redirect model only** — no card data touches ULMS (06).
- Reconciliation job: rail settlement file (where available) vs `payment`
  rows; mismatch → recon queue task (prototype's recon screens map here).
- Refunds/reversals as separate dual-authorized workflow (never automatic).
- Sandboxes: bKash/Nagad sandbox tokens (env-provided), BEFTN via bank CBS
  file channel in pilot (see §4), card via PSP hosted page.

## 4. ABC CBS Integration (pilot bank)

- Reality: CBS interfaces vary per bank; pilot uses **file-based GL/BEFTN
  batch exchange** (SFTP + agreed layouts) + REST where ABC exposes it —
  adapter isolates this; productization adds per-bank CBS adapters later.
- `CbsPort`: `postGlBatch(jvRows)`, `getAccountBalance`, BEFTN instruction
  files; reconciliation reports daily (counts + sums, zero-sum proof).

## 5. SMS / E-mail / Notification Gateways

- `SmsPort`/`MailPort` with provider adapters (bank-preferred BD gateways);
  bilingual template engine in mod-platform (prototype's bilingual strings are
  the seed catalog); opt-in/out honored; delivery receipts logged.
- Critical messages (OTP, sanction, overdue) retry with backoff + fallback
  provider; all sends audit-referenced.

## 6. Outbound Regulatory Files (CL-1..5, EDW, Basel, Large-loan forecast)

- Generated by mod-compliance into WORM staging (object-lock), sign-off chain
  (preparer→checker→compliance — prototype regcon flow), then SFTP upload per
  BB calendar; `regulatory_return` tracks status/due/receipt like the prototype.

## 7. Connector Governance

- One ADR per external system (protocol, auth, limits, failure policy).
- Contract tests in CI + sandbox smoke in UAT nightly (only for enrolled).
- Timeouts: connect 3s / read 10s (files 60s); retries idempotent-only.
- Data egress allow-list (NetworkPolicy) per 10 §3 — CIB/NIDW/rails endpoints
  only; changes go through security review (06).
