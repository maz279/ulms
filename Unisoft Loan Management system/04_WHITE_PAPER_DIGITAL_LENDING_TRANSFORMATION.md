This white paper examines the current state of lending in Bangladesh, the global trends in digital lending, the regulatory imperative for modernization, and presents a comprehensive framework for digital lending transformation anchored by the **Unisoft Loan Management System (ULMS)**.

4. **Local Expertise Matters** - Bangladesh-specific requirements demand local solutions

### BRPD Circular 15/2024: Loan Classification Framework

#### The New Seven-Stage Classification System

Effective April 1, 2025, Bangladesh Bank introduced a new loan classification framework:

| Stage | Classification | Overdue Days | Provisioning | System Requirement |
|-------|---------------|--------------|--------------|-------------------|
| STD-0 | Standard (Current) | 0 days | 1% | Auto-calculation required |
| STD-1 | Standard (Watch) | 1-30 days | 1% | Auto-migration required |
| STD-2 | Standard (Caution) | 31-60 days | 1% | Auto-migration required |
| SMA | Special Mention | 61-90 days | 5% | DPD tracking required |
| SS | Substandard | 91-180 days | 20% | Provision calculation |
| DF | Doubtful | 181-360 days | 50% | Provision calculation |
| B/L | Bad/Loss | >360 days | 100% | Write-off processing |

**System Implications:**
- Real-time DPD calculation is mandatory
- Automatic classification migration is required
- Provisioning must be automatically calculated and posted
- CL-1 to CL-5 reports must be auto-generated
- Manual processes are no longer feasible

### IFRS-9 ECL Implementation (Mandatory December 2027)

#### Expected Credit Loss Model

| Stage | Condition | ECL Calculation | Implementation Complexity |
|-------|-----------|-----------------|-------------------------|
| **Stage 1** | Good standing | 12-month ECL | Medium |
| **Stage 2** | Significant credit risk increase | Lifetime ECL | High |
| **Stage 3** | Credit impaired | Lifetime ECL (100%) | High |

**System Requirements:**
1. Forward-looking macroeconomic scenario modeling
2. Probability of Default (PD) calculation
3. Loss Given Default (LGD) estimation
4. Exposure at Default (EAD) measurement
5. Historical data analysis (minimum 5 years)
6. Real-time data aggregation

## 6. TECHNOLOGY CONSIDERATIONS

### Architecture Options

#### 1. Monolithic vs. Microservices

| Aspect | Monolithic | Microservices |
|--------|------------|---------------|
| **Development** | Simpler initial development | More complex but flexible |
| **Deployment** | All-or-nothing deployments | Independent service deployment |
| **Scaling** | Vertical scaling only | Horizontal scaling |
| **Technology** | Single technology stack | Best tool for each service |
| **Maintenance** | Easier initially | More complex long-term |
| **Resilience** | Single point of failure | Service isolation |

**Recommendation:** Microservices architecture for banks needing flexibility and scalability.

#### 2. Deployment Models

| Model | Description | Best For |
|-------|-------------|----------|
| **On-Premise** | Traditional deployment in bank data center | Banks with strict data residency requirements |
| **Private Cloud** | Dedicated cloud environment | Banks needing scalability with control |
| **Hybrid Cloud** | Combination of on-premise and cloud | Banks with diverse workloads |
| **Public Cloud** | Shared cloud infrastructure | Digital banks, fintechs |

**Recommendation:** Start with on-premise or private cloud, with migration path to hybrid.

#### 3. Technology Stack Recommendations

| Component | Recommended Options | Rationale |
